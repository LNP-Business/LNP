# 11 — LNP front end

The CRM stays in LNP with the existing design system (functional spec §2): Cockpit as
reference, Fraunces / IBM Plex, `#F6F4EF`, segmented control top bar, "i" Page method on every
screen, confirmation popup before every delete, designed at 1440 px (no phone layout). UI text in
English, never "closer". The CRM keeps its own English / French switch.

## 1. What already exists and must be reused

| Existing | Use it for |
|---|---|
| Web edition sign-in, `members` roles, `/api/me` (role + screens) | Who is signed in; no new auth |
| `web/public/skl-web.js` Supabase client (URL + anon key from `/api/config`) | All CRM reads, RPC calls and Realtime — do not load a second supabase-js |
| `store.js` alert engine, `config/alerts`, `inbox` | CRM alerts c1–c18 (10 §2) |
| "You are" member id (`sales`, `romain`…) | Map to `crm_members.member_key` |
| Settings › Access (`app_metadata.screens`) | New CRM screens get Access entries |
| Demo mode when opened as a plain file | CRM demo data (the current sample leads) |

## 2. Data layer (`skl-os/crm/data.js`)

Functions: `listCycles(filters)`, `getCycle(id)` (cycle, person, calls, current outcomes, events,
deal, payments, analyses, nurture), `declareOutcome`, `addNote`, `resolveUnmatched`,
`createCheckout`, `cancelAutoClose`, `setNurture`, `approveOutbound`, `updateCrmConfig`, Realtime
subscriptions on `crm_cycles`, `crm_events`, `crm_alerts`. Writes go only through the RPCs of
02 §5. In demo mode the same functions return sample data and save nothing.

`crm_doc.html` (ALKIMIY Lite, generated by `skl-os/gen_crm.py` from `uploads/ALKIMIY_Lite.html`)
switches its persistence from `localStorage` to this layer. Change the source and the generator,
never the generated file.

## 3. Moving the existing browser data

The current CRM data sits in each person's browser. Phase 1 adds:

1. In the current CRM, an "Export my CRM data" action (JSON of its `localStorage`).
2. An admin "Import CRM data" screen that maps it to `crm_people`, `crm_cycles`, `crm_calls`,
   `crm_call_outcomes` and `crm_events` with `source = 'import'`, shows a dry-run summary
   (people, cycles, duplicates by email/phone) and imports on confirmation.
3. Leads still in the old "New" stage (never booked) are imported as people without a cycle
   (out of scope D1); a later booking opens their cycle.

## 5. KPIs (SQL views `crm_kpi_*`, `security_invoker = true`)

Show rate, no-show rate, disqualification rate, closing rate (won / cycles with a held call,
excluding disqualified), payment rate (won / yes), calls per win, median hours per stage vs target,
median cycle hours, median sales reply hours, follow-ups on time, outcome discipline, not-recorded
calls, abandoned leads, loss reasons, sold vs collected, nurture reactivations and cash from
nurture, call quality. Filters: sales, product, origin, period. Exact definitions follow F1–F4.

## Lead record, Ma journée and Pipeline moves (2026-11-05)

- **Lead record** (web edition): on the left the lead's sales cycle as a vertical feed by day, oldest first, newest in view,
  with the filters All · Calls · Messages · Payments (E-mails when there are some); on the right « À faire » (the outcome to
  declare, the call to prepare, the reschedule or follow-up, with « Fait » saving what was done as a note), the sales calls
  and the call analysis. One renderer: `skl-os/crm/lead_feed.js` (`SKL_LEADFEED.feed`, `.todo`), from
  `SKL_CRM.salesCycleView`. The horizontal timeline stays in CRM › Sales cycle.
- **Ma journée**: each card shows the same feed between its facts and its action.
- **Pipeline moves** (`skl-os/crm/outcome_ui.js` › `sklMove`; the card drag and drop, the lead record's Status menu and the
  Leads list's status all go through it):

| Lead | Dropped on | What opens |
|---|---|---|
| a past call with no outcome | Absent, Won, Lost, Disqualified, next round | the outcome form, filled in for the column (`crm_declare_outcome`) |
| a past call with an outcome | Absent, Won, Lost, Disqualified | the same form as a correction (the outcome is superseded) |
| no past call | Lost, Disqualified | the closing form: reason of the list, note (`crm_close_cycle`, 045) |
| lost or disqualified | an active column | a confirmation, then `crm_reopen_cycle` (045) |
| won | anywhere | a message: a paid sale does not move |
| any | New, Long follow-up, a round not booked yet, No booking | a message: the CRM computes that column |

  Viewers move nothing. Test: `node skl-os/crm/pipeline_moves_live.js $PWD/skl-os/skl-os-en.html <dir>`.
